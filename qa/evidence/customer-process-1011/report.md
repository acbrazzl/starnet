## Proposed process changes

1. **Choose a customer-backed slice and its acceptance boundary before coding.** Record original report, affected artifact/platform/provider, exact reproduction or missing evidence, owner, and sibling entrypoints. If no causal reproduction exists, the deliverable is an evidence request, not a guessed fix.
2. **Require one failing behavioral receipt and a boundary matrix.** Source-string assertions may protect deliberate contracts but cannot replace outcome checks. Include wrong/empty/late responses, restart and one sibling route. The deep sweep's stale remote-answer assertion led to real phone/voice siblings; it was useful to investigate rather than delete the check mechanically.
3. **Serialize candidate integration and preserve receipts by revision.** The measured release delta is 299 commits/409 paths (140 core paths) from 0.13.2 to a20ffa71f. That is churn exposure, not a regression rate. Merge small owned slices; run the combined gate once on the locked candidate, then accept the exact packaged bytes. A later successful retry does not explain a timeout; retain failure class and environment.
4. **Keep separate source, artifact and customer states.** Existing register fields already support this. Use them in release decisions; never collapse wontfix or source-fixed into customer recovery. Intake owners should reconcile each resolved report to its particular artifact and retest evidence, without duplicating Gmail/Whop/GitHub outreach.
5. **Turn the workspace incident into an enforced preflight.** This lane caused shared asset deletion through mounted junctions; concurrent sparse work complicated recovery. Before checkout/sparse/read-tree/mirror/cleanup operations, detect reparse points and verify physical ownership. Detach only verified owned links, never recursively remove their targets. Full gates should use physical staged assets where copy checks require them. A worktree alone is not isolation when its paths alias shared writable data.
6. **Measure performance only for a selected incident.** Pin model, effort, station, prompt/tool posture and revisions; retain cache/read/write usage, main/aux calls, turns, first token and verified-output latency. Review PR103 before implementing persistent CLI work. No universal Hermes multiplier, zero-budget workaround (zero means unlimited), or inferred refund follows from the old probes.
